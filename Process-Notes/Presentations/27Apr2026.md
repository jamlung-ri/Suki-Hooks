**Deck Title: Connecting Suki Hooks To Canonical Measures**

**Slide 1: Why We Built This Framework**  
Purpose: Introduce the presentation goal.  
Main message: We are translating Suki product capabilities into measurable canonical outcomes.  
Content:
- Suki has multiple product “hooks” that may affect clinical, operational, financial, and experience outcomes.
- The canonical measures give us a shared measurement language.
- The matrix connects each hook to the data needed to evaluate it.
- The goal is not to measure everything; it is to prioritize the highest-value, most defensible measurements.
Visual: Flow diagram: `Suki Hooks -> Data Sources -> Canonical Measures -> Evidence / Decisions`.

**Slide 2: What We Mean By “Suki Hooks”**  
Purpose: Define hooks in plain language.  
Main message: Hooks are specific Suki capabilities that create measurable intervention points.  
Content:
- A hook is a product capability that could plausibly move one or more outcomes.
- Priority hooks for this measurement effort:
  - **H1 Ambient Documentation**
  - **H3 Problem-Based Charting**
  - **H4 Multilingual Support**
  - **H5 Personalization**
  - **H7 Audio / Transcript Access**
  - **H8 Orders Staging**
  - **H9 Coding Suggestions**
  - **H15 Evidence Linking**
- Other hooks remain relevant, but these are the highest-priority pathways for near-term evaluation.
Visual: Layered stack with **H1 Ambient Documentation** as the foundation and other hooks layered above it.

**Slide 3: Priority Hooks At A Glance**  
Purpose: Give the Suki team a fast map of the major hooks.  
Content:
- **H1 Ambient Documentation**: Converts encounter conversation into structured clinical documentation.
- **H3 Problem-Based Charting**: Organizes documentation by problem and generates structured diagnosis codes.
- **H9 Coding Suggestions**: Uses structured diagnosis output for coding, HCC, E&M, and revenue cycle workflows.
- **H5 Personalization**: Allows provider-level note style and verbosity preferences.
- **H15 Evidence Linking**: Links generated note content back to transcript evidence.
- **H4 Multilingual Support**: Supports multilingual conversations with English note generation.
- **H8 Orders Staging**: Stages orders for clinician review and signature.
- **H7 Audio / Transcript Access**: Enables access to audio/transcript artifacts for research and audit.
Visual: Table with columns: Hook ID + name, product capability, measurement opportunity, priority level.

**Slide 6: Method And Data Sources**  
Purpose: Explain how the hook-to-measure framework was built and what evidence sources it uses.  
Main message: The matrix combines Suki product documentation, API-visible data artifacts, connected-system data requirements, and canonical measure definitions to identify practical measurement pathways.  
Content:
- Method:
  - Inventory the known Suki hooks from developer documentation, product materials, whitepapers, blog posts, press releases, and demo notes.
  - Map each hook to canonical measures using a mechanistic pathway: what the product does, what data it produces, and which outcome it could plausibly affect.
  - Classify each hook-measure relationship as direct, indirect, speculative, or not meaningful.
  - Separate what can be measured from Suki-native data from what requires EHR, claims, RCM, survey, or chart-review data.
  - Prioritize measures based on feasibility, signal clarity, actionability, and existing external evidence.
- Primary data sources:
  - Suki developer documentation and API/SDK artifacts.
  - Suki product documentation, whitepaper, blog posts, press releases, and demo materials.
  - The 25 canonical measure definitions from the ACI corpus.
  - Published and grey-literature evidence on ambient documentation, coding, EHR time, burnout, note quality, patient experience, and safety.
- Data-source categories:
  - Suki-native: sessions, status, transcripts, generated notes, structured diagnoses, source transcript links, feedback.
  - EHR-linked: audit logs, note timestamps, order actions, problem list updates, total EHR time.
  - Revenue-cycle linked: claims, RVUs, final codes, denials, CDI queries, coder review.
  - Prospective study data: provider surveys, patient surveys, expert note review, safety audits.
Visual: Four-source evidence model: `Product/API evidence + Canonical measures + External literature + Connected-system data -> Prioritized measurement plan`.

**Slide 9: Example Hook: H3 Problem-Based Charting**  
Purpose: Explain **H3 Problem-Based Charting** as structured clinical output, not just note formatting.  
Main message: **H3 Problem-Based Charting** creates a measurable bridge from conversation to structured diagnosis capture.  
Content:
- **H3 Problem-Based Charting** organizes note content around discussed problems.
- It compares seeded problem context with output diagnoses.
- It generates structured ICD-10 / IMO diagnosis artifacts.
- The input-output diagnosis delta can be used as a completeness and coding signal.
Example API calls:
```http
POST /session/{id}/context
GET /session/{id}/structured-data
GET /encounter/{id}/structured-data
```
Example payload:
```json
{
  "diagnoses": {
    "values": [
      {
        "codes": [{"code": "I10", "type": "ICD-10"}],
        "diagnosis_note": "Hypertension"
      }
    ]
  }
}
```
Visual: EHR problem list input -> encounter discussion -> Suki structured diagnosis output.

**Slide 10: Example Hook: H9 Coding Suggestions**  
Purpose: Show **H9 Coding Suggestions** as the revenue cycle layer on top of **H3 Problem-Based Charting**.  
Main message: **H9 Coding Suggestions** is measured by comparing Suki-derived coding outputs to claims, coder review, and denial outcomes.  
Content:
- **H9 Coding Suggestions** depends on **H3 Problem-Based Charting** structured diagnosis output.
- **H9 Coding Suggestions** supports **CM-21 Coding Accuracy** and **CM-20 Financial Productivity**.
- Potential outputs include ICD-10 accuracy, E&M level, HCC capture, RAF impact, denial rate, and CDI query reduction.
- HCC mapping can be computed from structured ICD-10 output before claims are finalized.
Example computation:
```text
H3 Problem-Based Charting ICD-10 output
-> CMS HCC v28 crosswalk
-> expected HCC categories
-> expected RAF impact
```
Visual: `Structured diagnoses -> Coding suggestions -> Claims / RCM -> Revenue and accuracy measures`.

**Slide 11: Example Hook: H15 Evidence Linking**
