CM-01 — Clinician Burnout and Exhaustion

NB — Net Benefits Provider Wellbeing Also known as: Work Exhaustion  ·  Emotional Exhaustion  ·  Burnout Syndrome

Unit

Unit
PFI Work Exhaustion subscale score (1–5)
↓ Lower is better

Provider-reported emotional exhaustion, depersonalization, and interpersonal disengagement from clinical work — the core burnout syndrome — measured via a validated psychometric instrument administered at defined intervals around Suki adoption. Distinct from in-encounter cognitive load (CM-02) and professional fulfillment (CM-03), which are adjacent but dissociable constructs.

Gold Standard
Stanford Professional Fulfillment Index (PFI), Work Exhaustion subscale — 10-item, 1–5 scale (higher = worse). The instrument used in the strongest external RCT (Afshar 2025b, n=66), which found a −0.44 reduction.
Default / Practical
Mini-Z / Mini-Z 2.0 — 10-item brief burnout screen, 10–50 scale (higher = better, opposite polarity from PFI). Lower respondent burden; widely used in quality-improvement contexts and proposed as the Phase 0/Phase 3 instrument.
⚠ Ambiguities to Resolve
  • The baseline problem. A true pre/post comparison requires a baseline survey administered before Suki go-live. If Suki is engaged retrospectively, this window is permanently lost — CM-01 then can only be measured as a cohort-level dose-response comparison (heavy vs. light users at follow-up), not an individual-level pre/post change.
  • Self-report inflation. Self-report-only studies (Shah 2024: −1.94 on the PFI Work Exhaustion subscale) substantially overstate effect size relative to the RCT (Afshar 2025b: −0.44) — a gap expected from volunteer/selection bias in non-randomized designs. Do not present self-report-only deltas as equivalent to RCT effect sizes.
  • Instrument-direction mismatch. PFI Work Exhaustion is 1–5 where higher = worse; Mini-Z is 10–50 where higher = better. If a site switches instruments between baseline and follow-up, scores must be normalized to a common direction before any comparison is made.
  • Individual-level linkage vs. anonymity. Linking a provider's baseline survey response to their post-deployment utilization tier requires either non-anonymous administration (reduces candor on a sensitive topic) or a study-specific pseudonymous code maintained outside Suki.

Algorithm

1 Survey Instrument Scoring — Dose-Response Cohort Comparison Phase 0 / Phase 3 administration

Produces a cohort-level burnout score for each administration wave, compared across Suki utilization tiers rather than (or in addition to) a simple pre/post pooled comparison. The score is expected to decrease (PFI scale) after Suki adoption, with the largest decrease in the heaviest-utilization cohort.

CM-02 — Cognitive and Task Load

NB — Net Benefits Provider Wellbeing Also known as: Mental Workload  ·  NASA-TLX  ·  Physician Task Load

Unit

Unit
NASA-TLX / PTL score (0–100)
↓ Lower is better

The mental effort, time pressure, and frustration a clinician experiences during or immediately after a clinical encounter — the in-the-moment cognitive demand of documentation, measured via the NASA Task Load Index or a brief physician-specific adaptation. Distinct from CM-01 (sustained emotional exhaustion over weeks-to-months) and CM-04 (objective documentation duration).

Gold Standard
NASA-TLX (full) — 6-domain instrument (Mental Demand, Physical Demand, Temporal Demand, Performance, Effort, Frustration), 0–100 per subscale. Used in Bracken 2025, PHTI 2025, Omon 2025, Stults 2025. Frustration and Temporal Demand subscales are most relevant to documentation-specific burden.
Default / Practical
Physician Task Load Index (PTL) — 4-item NASA-TLX adaptation, 0–100 scale (lower = better), used in Shah 2024. Lower respondent burden, suitable for repeated or frequent administration (e.g., end-of-shift).
⚠ Ambiguities to Resolve
  • The timing problem. NASA-TLX validity depends on proximity to the encounter — ideally administered immediately post-encounter, not weeks later. Suki has no mechanism to trigger a micro-survey on session completion, so administration falls back to end-of-shift or periodic, which introduces recall aggregation across multiple encounters.
  • Composite vs. subscale. Full NASA-TLX (6 domains) vs. Frustration/Temporal Demand subscales only vs. PTL (4 items) are not interchangeable scores. Pick one operationalization and apply it consistently across the comparison window.
  • Pathway attribution. Four distinct hooks (H1 ambient documentation, H8 orders staging, H10 pre-visit summaries, H11 chart Q&A) plausibly reduce cognitive load through different mechanisms. A NASA-TLX change cannot, by itself, identify which pathway drove it — pathway isolation requires session-level exposure flags not yet available.

Algorithm

1 Survey Instrument Scoring — End-of-Shift Dose-Response Comparison Periodic administration

Produces a cohort-level workload score, compared between heavy- and light-utilization Suki users at the same point in time (dose-response), since a true pre/post comparison requires the same pre-deployment baseline timing discipline as CM-01. The score is expected to be lower (PTL/NASA-TLX scale) in heavier-utilization cohorts.

CM-03 — Professional Fulfillment and Meaningfulness

NB — Net Benefits Provider Wellbeing Secondary / Exploratory Also known as: Meaning in Work  ·  PFI Professional Fulfillment Subscale

Unit

Unit
PFI Professional Fulfillment subscale score (1–5)
↑ Higher is better

Provider-reported positive engagement with clinical work — the presence of meaning, reward, and satisfaction in the work itself. This is the positive pole of the wellbeing spectrum, dissociable from CM-01 (absence of exhaustion). Removing a negative (burnout) does not imply adding a positive (fulfillment), and the strongest available evidence shows exactly this dissociation.

Gold Standard
Stanford Professional Fulfillment Index (PFI), Professional Fulfillment subscale — 6-item, 1–5 scale (higher = better). The instrument used in Afshar 2025b. If a full PFI is administered for CM-01, this subscale is collected "for free" in the same instrument.
Default / Practical
Custom meaningfulness-of-work and work-life balance Likert items (Afshar 2025b, Boyter 2025, Duggan 2025) — conceptually adjacent supplements with weaker instrument validation; not a substitute for the PFI subscale.
⚠ Ambiguities to Resolve
  • Expected null result. Afshar 2025b (RCT, n=66) found professional fulfillment increased at p=0.04, which missed the pre-specified alpha of 0.025, while burnout (CM-01) decreased significantly (−0.44). The expected outcome for CM-03 is a null result — this should be stated up front in any report, not discovered after the fact.
  • Low actionability. The H1 deep-dive scores CM-03 as Tier 3 (7/12), driven by Low Actionability — no current Suki hook is designed to act on meaning, reward, or engagement (unlike CM-01/CM-02, where H1/H8/H10/H11 plausibly act on burden or cognitive-load mechanisms). Even a clean measurement gives no lever to pull.
  • Do not separately scope. If a full Stanford PFI is administered for CM-01, the Professional Fulfillment subscale is collected in the same instrument at no additional respondent burden. Standing up a separate CM-03 data-collection effort is not recommended.
  • Framing risk. Reporting CM-03 as a standalone, primary value-proposition metric risks being read as "Suki doesn't improve wellbeing" when the more accurate reading is "Suki improves one wellbeing construct (burnout) and not a different, dissociable one (fulfillment)."

Algorithm

1 Survey Instrument Scoring — Bundled Dissociation Check Same administration as CM-01 PFI

Produces a cohort-level professional-fulfillment score from the same Phase 0 / Phase 3 PFI administration used for CM-01, reported alongside the CM-01 burnout delta as a dissociation check, not a standalone outcome. The expected result is a flat or non-significant change in this score even where CM-01's burnout score decreases.

CM-04 — Documentation Time

NB — Net Benefits Documentation Efficiency Also known as: Time in Notes  ·  Note Completion Time  ·  Documentation Duration

Unit

Unit
Documentation minutes per encounter
↓ Lower is better

A documentation minute is any minute of activity attributable to note creation or editing for a given encounter — counted from encounter open through final note signature, including post-signature addenda. Measured via EHR audit-log telemetry (preferred) or Suki session duration (fallback). Each minute is attributed to the encounter in which the documentation occurred.

Gold Standard
EHR audit-log telemetry (e.g., Epic Signal / UAL) capturing time-stamped, per-user documentation activity bounded to note creation and editing. Preferred — objective and captures the full note-to-sign lifecycle inside the EHR.
Default / Practical
Suki session duration: start-to-end timestamp per dictation or ambient capture session. Use when EHR audit-log data are unavailable. Captures in-app documentation time only; misses editing and signing that occurs inside the EHR after the Suki session ends.
⚠ Ambiguities to Resolve
  • Per-encounter vs. per-note vs. per-day. Documentation time is reported per encounter, per note, or per provider per day across the literature. These units are not interchangeable. Choose one and apply it consistently across the pre- and post-adoption windows.
  • Self-report vs. objective telemetry. Self-reported documentation time overestimates improvement by 3–6× relative to EHR audit-log data (Ma 2025; PHTI 2025). Do not mix self-report and objective sources in the same analysis.
  • What counts as documentation time. Some EHR telemetry fields include inbox, chart review, or order entry in their “documentation time” metric. Confirm whether your EHR field is scoped to note creation and editing only, or to broader EHR activity. The latter overlaps with CM-07 (Total EHR Time).

Tier 1 (Preferred) — Sessionized Active Authoring Time
Collapse a note’s edit events into work sessions (gap threshold: 10 min default, tunable). Sum only within-session durations; discard idle gaps. Output: average active authoring minutes per note per provider.

Pseudocode — Tier 1 (sessionized)

Tier 2 (Fallback) — Create→Sign Elapsed Span
Single subtraction per note: wall-clock time from CREATE_INSTANT_DTTM to LST_FILED_INST_DTTM. Simpler but includes idle periods — overstates active work.

⚠ Proxy Caveats & Guardrails
  • Event-gated, not keystroke-gated. This measures wall-clock between logged edit events, not keystroke-active time. Tier 1 is less sensitive to long idle gaps than Tier 2, but is still a proxy. Report it as “note-authoring time,” not “documentation time.”
  • Floor estimate, not full Signal. Signal/UAL captures note authoring, chart review, inbox, and order entry. This proxy captures only note-authoring events — a subset. Do not compare proxy minutes directly to Signal minutes without a correction factor.
  • Calibrate against Signal where possible. If any provider-period overlap between Signal and Clarity data exists, compute a correction factor rather than presenting proxy minutes as equivalent.
  • Multi-author notes. Attribution uses ENTRY_USER_ID. Resident or scribe edits on an attending’s note should not be charged to the attending.
  • Open questions before deployment: (1) What is the actual event density in NOTES_HISTORY_LOG — does it log intermediate edits or only create/sign endpoints? (2) Is any Signal extract available for calibration on a provider subset? (3) What session threshold (5, 10, or 15 min) best fits local workflows?

CM-05 — After-Hours Documentation

NB — Net Benefits Documentation Efficiency Also known as: Pajama Time  ·  Work Outside Work  ·  After-Hours EHR Time

Unit

Unit
After-hours documentation minutes
↓ Lower is better

A documentation minute is after-hours if it falls outside the provider's working hours on that calendar day. Minutes are counted from encounter open through final note signature, including any post-signature addenda and edits.

Gold Standard
Per-provider or per-specialty working hours, as configured by the care setting. Preferred — avoids systematic misclassification across specialties with non-standard hours.
Default / Practical
Before 09:00 or after 17:00 on weekdays; any time on Saturday or Sunday. Use when per-provider scheduling data are unavailable.
⚠ Ambiguities to Resolve
  • Working hours vary by specialty. Surgeons may work 09:00–21:00; a 9–5 default over-counts after-hours time for them and cannot be compared across specialties without adjustment.
  • When does documentation end? We recommend counting through final signature and all addenda; stopping at initial note closure understates after-hours activity and is not directly comparable across implementations.
  • Pre-encounter prep vs. after-hours. Early chart review (e.g., 06:00 before rounds) may be classified as after-hours under a fixed window even within a provider's normal practice. Provider-level scheduling resolves this; the 9–5 default does not.

CM-06 — Chart Closure Timeliness

EFF — Documentation Efficiency Tier 1 — 10/12 Also known as: Same-Day Encounter Closure  ·  Chart Closure Time  ·  24-Hour Documentation Deficiency Rate  ·  Pre-Next-Visit Closure

Unit

Unit
% of encounters with notes closed within 24 hours
↑ Higher is better

Whether and how quickly clinical notes are completed and signed — a documentation-completion-behavior measure, distinct from how long the note took to write (CM-04). A note can be drafted in 3 minutes (fast CM-04) and sit unsigned for 2 days (poor CM-06), or take 15 minutes to draft but be signed immediately. The canonical definition prefers the 24-hour, duration-bounded window for pre/post evaluation over the stricter calendar-bounded "same-day" convention.

Gold Standard
EHR-confirmed note-signature timestamp vs. encounter-end timestamp, reported as a 24-hour closure rate (%) or 24-hour deficiency rate (% — the complement). This is the basis for Boyter 2025/KLAS's −41% chart-closure-time finding (UAL data) and FMOL's 84% improvement in notes closed within 7 days.
Default / Practical
Suki draft-availability rate within 24 hours — using the elapsed time between the session-completion timestamp (status = completed) and the encounter-end timestamp, bucketed the same way as the EHR-confirmed measure. A leading proxy, not the canonical measure itself (see ambiguity below).
⚠ Ambiguities to Resolve
  • Same-day vs. 24-hour window. "Same-day" is calendar-bounded — a 4:45 PM encounter closed at 7:00 AM the next day fails "same-day" despite closing in under 15 hours. "Within 24 hours" is duration-bounded and does not penalize late-day visits. The canonical definition recommends the 24-hour window for pre/post evaluation; document which convention any given site uses, since Suki's own bucket and an EHR-reported "same-day" rate will diverge for reasons unrelated to documentation behavior.
  • Overlap with CM-04. The "time to chart" framing risks restating CM-04 (Documentation Time). CM-06's scope is held strictly to completion/signature behavior, not drafting duration — even though both measures draw on the same underlying Suki session-timestamp data.
  • Draft-availability vs. signature. Suki's status = completed event marks the note draft as ready, not signed. The clinician still has to review and sign it in the EHR. Any Suki-only report of "closure" should be explicitly labeled draft-availability until EHR signature data is confirmed available.
  • Bucket field source-of-truth unconfirmed. The Suki-EHR crosswalk already defines same_day_count, next_day_count, two_three_day_count, four_five_day_count, six_plus_day_count — but whether their "day signed" component is EHR-sourced (answers CM-06 directly) or derived from Suki's own completion timestamp (answers draft-availability) is unconfirmed.
  • Pearlman 2025 benchmark unverified. Its "Time to Close Encounter" outcome is not yet confirmed to measure note signature vs. a broader workflow event (e.g., room turnover, discharge) — treat as a candidate, not confirmed, benchmark.

CM-07 — Total EHR Time

NB — Net Benefits EHR Efficiency Also known as: Total EHR Time  ·  Login Time  ·  Active EHR Time  ·  EHR Burden

Unit

Unit
Total EHR minutes per encounter
↓ Lower is better

A total EHR minute is any minute of logged activity in the EHR system by a given provider, across all task types — note creation, inbox management, order entry, results review, and any other EHR interaction. Minutes are summed per provider per encounter-equivalent period and normalized to completed encounters.

Gold Standard
Full EHR audit-log telemetry capturing all activity types across all EHR modules (documentation, inbox, orders, results, admin). Preferred — gives the broadest and most complete view of EHR burden.

Documentation time + inbox time only, when full audit-log is unavailable. These two components are the most reliably extracted from most EHR telemetry systems and account for the largest share of total EHR time.

CM-08 — Note Completeness and Omission Rate

IQ — Information Quality Pilot / Calibration Design Also known as: Omissions  ·  Omission Errors (%)  ·  Thoroughness (PDQI domain)  ·  Completeness

Unit

Unit
% of notes with ≥1 clinically relevant element omitted (below Thoroughness threshold)
↓ Lower is better

The absence of clinically relevant information from an AI-generated note — content that was present in the encounter (or in a reference note) but does not appear anywhere in the generated note. Distinct from CM-09 (Note Inaccuracy Rate), which measures content that is present but wrong. Omissions are the dominant error type in ambient documentation: all 5 simulation studies in this corpus that categorize error types find omissions account for 71–86% of all errors, making completeness the single most consistent Information Quality finding in the literature.

Gold Standard
PDQI-9 / PDSQI-9 Thoroughness domain — 5-point Likert subscale scored by physician raters against a reference (transcript or physician-authored note). PDSQI-9 is the AI-note-adapted version; the same LLM-as-judge validation pattern used for CM-09's Accuracy domain (Afshar 2025b) applies to Thoroughness.
Default / Practical
Reference-checklist coverage check using Suki's source_transcripts[] evidence-linking primitive in reverse — flags transcript-evidenced clinical elements that have no corresponding sentence anywhere in the generated note. Used as a pre-screening signal and sampling frame for the rating pipeline.
⚠ Ambiguities to Resolve
  • The Missing Feedback Loop (shared with CM-09). Suki never sees the physician's post-generation edits. Without the EHR's final signed note and edit/version history, CM-08 can only be measured against the transcript, not the clinician's final accepted note, and only via one-off rater exercises rather than continuous monitoring.
  • Wide published omission rates (71–86%). Kernberg 2023 (86%), Arko 2025 (71%) — rates vary with the reference standard used (transcript-based vs. physician-authored-note-based) and with how "clinically relevant element" is operationalized. The element checklist and reference standard must be fixed before a rate is reported or compared across sources.
  • amendment_count is a weak, indirect telemetry proxy. The vendor metrics mapping links an "amended or addendum note count" field to CM-08 as an indirect proxy. It conflates omission-driven re-opens with accuracy corrections (CM-09) and unrelated edits (formatting, dictation fixes, coding changes) — it should not be used as a standalone completeness signal, only as a low-cost screening input pending validation against rater scores.

CM-10 — Note Quality Overall

IQ — Information Quality Composite / Rollup Measure Also known as: PDQI-9 Score  ·  PDSQI-9  ·  SAIL Score  ·  Overall PDQI Score  ·  Global Rating  ·  Documentation Quality

Unit

Unit
Composite PDQI-9/PDSQI-9 quality score (9 domains, 1–5 each; range 9–45)
↑ Higher is better

An aggregate quality rating of the AI-generated note across all nine PDQI-9/PDSQI-9 domains: Accuracy, Thoroughness, Usefulness, Organization, Comprehensibility, Succinctness, Synthesis, Consistency, and an overall impression item. It is explicitly a rollup: two of its nine domains are independently tracked as their own canonical measures elsewhere in this corpus — Accuracy is CM-09 (Note Inaccuracy Rate) and Thoroughness is CM-08 (Note Completeness). The remaining six domains (Usefulness, Organization, Comprehensibility, Succinctness, Synthesis, Consistency) are captured only through this composite.

Gold Standard
PDQI-9 human-rater composite — the original validated 9-item instrument, 5-point Likert per item (max 45), designed for human-authored notes and widely used in simulation studies as the reference standard.
Default / Practical
PDSQI-9 LLM-as-judge composite — the AI-note-adapted version. Afshar 2025b validated an LLM-as-judge implementation against physician ratings (3.97–4.99/5.0 in that RCT), making fully automated composite scoring feasible at scale once agreement is established.
⚠ Ambiguities to Resolve
  • Raw scores are not self-interpreting. Kernberg 2023 reports approximate scale anchors of 26.2 ≈ "terrible or bad" and 36.6 ≈ "good or excellent" (their study mean: 29.7, closer to terrible) — without publishing the anchor points alongside a raw composite number, the score cannot be read as pass/fail or good/bad on its own.
  • Composite masks which domain moved. Because Accuracy (CM-09) and Thoroughness (CM-08) are two of the nine inputs, a stable or improving composite score can hide a decline in one domain offset by a gain in another. Always report the composite alongside its component domain scores, not as a replacement for them.
  • SAIL score is a different instrument. SAIL is a separate standards-based scoring approach, not numerically equivalent to a PDQI-9/PDSQI-9 sum or mean. Do not average or convert between instruments; report on separate tracks if both are collected.
  • Per-section and per-note-type scoring variants exist. Some studies apply PDQI by note section (e.g., SOAP Subjective / Plan) or by note type (progress note vs. discharge summary) rather than to the whole note. These variants are not interchangeable with a whole-note composite.

CM-11 — Note Length and Verbosity

IQ — Information Quality Automated NLP Text Metric Also known as: Note Length  ·  Word Count  ·  Lexical Diversity  ·  Documentation Length

Unit

Unit

↕ Direction not asserted — context-dependent

The length and lexical richness of an AI-generated note, measured as word count, character count, or lexical diversity (unique vocabulary / total words). Unlike CM-08, CM-09, and CM-10, this unit is fully automated — it can be computed directly from note text without a human or LLM rater, using either Suki-native note content or, if accessible, EHR note-text fields.

Note length is a secondary / proxy measure, not a quality measure in its own right. Longer notes can indicate greater thoroughness (fewer omissions, see CM-08) or over-generation and padding that increases physician editing burden (Wojda 2025, Shah 2025 flag verbosity as a specific concern). This card does not assert which interpretation applies — see the Expected Trend section below.

Gold Standard
Word count (tokenized, whitespace/punctuation-normalized) per note — the most directly comparable operationalization across papers and across note templates, since it is less sensitive to formatting than raw character count.
Default / Practical
Character count per note or per calendar week — often the only granularity available from EHR-side documentation-length telemetry (chars/week) when word-level tokenization access is not available.
⚠ Ambiguities to Resolve
  • Direction is genuinely ambiguous. Unlike every other measure in this batch, there is no single expected direction after Suki adoption. Longer notes may reflect improved thoroughness (which should co-occur with a falling CM-08 omission rate) or increased padding/over-generation (which physicians report as added editing burden). CM-11 should always be interpreted alongside CM-08 (Completeness) and CM-10 (Overall Quality) — never read as a standalone quality signal in either direction.
  • Word count, character count, and note-length ratio are not interchangeable. Note length ratio (AI note length / human-authored note length) requires a human-authored reference note for the same encounter, which may not exist in AI-first documentation workflows.
  • Lexical diversity is length-sensitive. Type-token ratio is mechanically higher for shorter notes; comparing raw TTR across notes of different lengths requires a length-normalization method (e.g., MTLD or a fixed-window TTR), not a raw ratio.

CM-12 — Automated NLP Evaluation Metrics

IQ — Information Quality Methodological / Calibration Tool Also known as: ROUGE Score  ·  BERTScore  ·  BLEURT  ·  F1 Score  ·  SAIL Score  ·  LLM-as-Evaluator Agreement

Unit

Unit
Automated similarity score (ROUGE-L, BERTScore F1, or token-level F1) between AI note and a reference note
↑ Higher = closer match to reference

This is a methodological measure, not a clinical outcome. CM-12 computes n-gram overlap (ROUGE), semantic similarity (BERTScore/BLEURT), or token-level precision/recall (F1) between an AI-generated note and a reference note. It does not assess Suki's documentation quality directly — it assesses whether an automated evaluation method (used to scale up CM-08/CM-09/CM-10 scoring) agrees closely enough with human judgment to be trusted.

Concretely: CM-12 is the correlation-validation step that answers "how do we know our LLM-as-judge pipeline for CM-08/CM-09/CM-10 is trustworthy?" — it is a calibration check for other measures' evaluation pipelines, not a longitudinal outcome measure of Suki's performance. See Expected Trend below.

Gold Standard
BERTScore / entity-level F1 — embedding-based semantic similarity, captures paraphrase-level overlap rather than exact wording, generally considered a stronger candidate for clinical text than raw n-gram overlap.
Default / Practical
ROUGE-1/2/L — n-gram overlap, cheap to compute, the most widely reported baseline in this literature. Per Moramarco 2022, a naive Levenshtein (edit) distance baseline performs comparably to BERTScore on clinical notes — metric choice should be validated per use case, not assumed from general-domain NLP benchmarks.
⚠ Ambiguities to Resolve
  • Expensive metrics may not earn their keep. Moramarco 2022's central finding: Levenshtein distance performs as well as BERTScore on clinical notes. Before committing to an embedding-based metric pipeline, benchmark it against a cheap edit-distance baseline on the specific note types in scope.
  • A high automated score does not certify clinical quality. Per the corpus Key Note, these are research tools, not clinical quality measures — a high ROUGE/BERTScore/F1 says the AI note textually resembles the reference, not that it is clinically accurate (CM-09) or complete (CM-08) on its own.
  • Requires a trusted reference note. Every variant of this metric needs a physician-authored or otherwise-trusted comparison note per encounter — the same reference-availability constraint noted for CM-11's note-length-ratio variant.
  • No fixed acceptability threshold exists in this corpus. Thresholds for "acceptable" ROUGE/BERTScore/F1 in clinical documentation must be locally calibrated against the human/LLM-judge ratings from the CM-08/09/10 pilots — general-domain NLP benchmarks (e.g., news summarization) do not transfer.

This establishes whether a given automated metric is trustworthy enough to supplement or pre-screen for the rating pipeline at scale — it is a tool-validation step, not a measure of Suki's clinical performance in its own right.

Unit

Unit

↑ Higher is better

Utilization is the share of a provider’s (or cohort’s) scheduled EHR appointments in a period for which an ambient note was created by Suki, computed as Ambient Notes Created ÷ EHR Appointments Scheduled, where EHR Appointments Scheduled = EHR Created Appointments − EHR Deleted Appointments. Gold Standard
Suki Admin Center Utilization metric — SAFE_DIVIDE(ambient_created, appt_ehr_count) from suki-dev.analytics.SukiUserUsage. This is Suki’s own finalized, cross-team-validated metric definition (tracked in a shared BigQuery validation sheet), already run in production against real customer data — not a first-attempt proxy.
Default / Practical
Raw ambient session / note count with no appointment-based denominator. Used only when appt_ehr_count has not yet been reliably ingested for a given customer — e.g., early in onboarding before the EHR scheduling feed into Suki has stabilized.
⚠ Ambiguities to Resolve
  • Literature-to-metric mapping is not one-to-one. Published “Utilization Rate” (Ma 2025: 55%), “Adoption Rate” (AAFP 2021: 60% post-trial), “Scribe Utilization Rate” (Afshar 2025: 65.4%), and “Active user count” are often used interchangeably in papers but map to at least three structurally different Suki Admin Center metrics (Utilization, Adoption Rate, Engagement Rate) with different denominators and different time windows. Confirm which Suki metric a paper’s definition actually corresponds to before reporting any cross-study comparison.
  • Individual vs. cohort denominator capping. Provider-level utilization queries cap the ratio at 1.0 (100%), but cohort/time-series/specialty-level queries do not apply this cap — a provider whose ambient-note count exceeds their EHR-scheduled appointment count in a period (e.g., walk-ins, add-on visits not yet synced, multiple notes per encounter) shows >100% in the aggregate view but is capped at 100% in the per-provider view.
  • Adoption Rate ≠ Utilization Rate ≠ Engagement Rate. Despite the literature corpus treating “Adoption Rate” as an alias of this canonical measure, Suki’s own Adoption Rate metric is a trial-to-paid conversion definition (session activity in a 31–60 day post-first-use window), Engagement Rate is a depth-of-use ratio (≥2 vs. ≥1 weekly ambient sessions), and Utilization is the appointment-coverage ratio. These are three genuinely different constructs currently bundled under one canonical measure — CM-13’s definition should be scoped or split going forward.
  • EHR Appointments Scheduled is Suki-ingested, not a live Epic pull. It is computed from Suki’s own ingestion pipeline (appt_ehr_count), synced every 24 hours — not a real-time EHR query. Discrepancies against a health system’s own scheduling reports should be expected and reconciled before external reporting.

CM-15 — Provider Satisfaction and Usability

US — User Satisfaction Provider Usability Also known as: Physician Satisfaction  ·  System Usability Scale (SUS)  ·  Ease of Use

Unit

Unit
System Usability Scale (SUS) score, 0–100 (68 = industry average)
↑ Higher is better

Provider-reported satisfaction with the ambient AI scribe tool, including perceived usability, ease of use, and overall acceptability — a subjective technology evaluation. Distinct from burnout (CM-01, an emotional/wellbeing outcome), from adoption behavior (CM-13, what providers actually do), and from adoption intention (CM-14, stated intent to continue). Recommendation likelihood and long-term-use items were reclassified into this measure during corpus derivation as closer to satisfaction than to intention.

Gold Standard
System Usability Scale (SUS) — validated 10-item instrument, 5-point Likert per item, scored 0–100 (industry average ≈ 68). Standard scoring: for odd-numbered items, subtract 1 from the response; for even-numbered items, subtract the response from 5; sum all 10 adjusted scores (range 0–40) and multiply by 2.5. The only formally named validated usability instrument in the corpus (Shah 2024).
Default / Practical
Ad hoc single- or multi-item Likert satisfaction scales, and UTAUT perceived-usefulness / perceived-ease-of-use constructs — the pattern actually used by 20 of the 21 papers in the corpus, since only one paper explicitly names the SUS.
⚠ Ambiguities to Resolve
  • No meaningful pre-exposure baseline. Unlike burnout (CM-01), usability cannot be rated before any use of the tool — there is no true "Phase 0" for SUS. The design below compares an early-experience wave (weeks 4–8) to a mature-experience wave (months 4–9), not a pre/post-adoption change.
  • Volunteer/self-selection inflation. Satisfaction is almost universally positive across the corpus, but most studies recruited volunteers or interested practitioners. Prasad 2025 is the critical counter-signal: providers with <2 years of virtual-scribe use showed satisfaction strongly negatively associated with tenure. Administer to a mandatory or randomly-sampled cohort, not an opt-in one, wherever feasible.
  • Product satisfaction vs. occupational satisfaction mislabeling. Some corpus aliases ("Employee Satisfaction," "Job Satisfaction" in Boyter 2025 and Galloway 2024) actually measure satisfaction with the AI product, not occupational/job satisfaction in the general sense. Item wording must make clear the referent is the tool, not the job, to avoid this conflation.
  • Instrument inconsistency across the corpus. Only Shah 2024 explicitly names the standardized SUS; the remaining 20 papers use non-standardized ad hoc items, limiting cross-study comparability. Standardizing on SUS for any Suki-sponsored evaluation would materially improve benchmarking.

Unit

Unit

↑ Higher is better

The degree to which clinicians perceive AI-generated documentation as accurate and dependable enough to act on without exhaustive verification. A direct single-item "Trust in AI" Likert rating administered as part of a controlled study, per Afshar 2025b (reported as a secondary RCT outcome) — the only quantitative instance of this construct in the corpus.

CM-19 — Clinical Patient Safety

OI — Organizational Impact Monitor — 6/12 (High Actionability) Scope Narrowing Applies Also known as: AHRQ Harm Score  ·  Patient Safety Events  ·  Likelihood of Psychiatric Intervention (reclassification candidate)

Unit

Unit
AHRQ Harm Score / adverse-event rate (gold standard) — documentation-completeness ↔ clinical-action odds ratio (near-term proxy)
↓ Lower harm = better

Patient harm outcomes associated with ambient AI documentation — adverse events, AHRQ harm scores, and gaps between what gets documented and what clinical action actually follows. The canonical measures corpus calls this "the most concerning and least studied outcome dimension" — only 9 papers touch it, most using simulated or survey data rather than real patient outcomes. H1 (ambient documentation) itself is rated ○ (none) for CM-19 — ambient note generation alone does not plausibly move a harm outcome. H8 (orders staging) and H11 (chart Q&A) are the hooks that introduce safety-relevant pathways.

Gold Standard
AHRQ Harm Score / formal adverse-event and incident reports — typically live in administrative/risk-management systems separate from the EHR proper, and are likely the hardest data of any canonical measure to access.
Default / Practical
Castro 2025 replication design: an adjusted odds ratio (aOR) linking a Suki-native documentation-completeness signal to EHR order/intervention data for the same encounters. Not itself a CM-19 finding until paired with a downstream clinical-action or harm signal — see Scope Narrowing below.
⚠ Scope Narrowing (Critical — Read Before Reporting Any Error-Rate Data)
  • True patient safety requires measured patient harm outcomes. Errors in documentation that do not demonstrate a downstream patient outcome are technical quality issues (→ CM-09 Note Inaccuracy Rate), not safety. Severity of error is not patient safety without evidence of patient harm.
  • Several commonly-cited "safety" items are likely misclassified absent outcome evidence: "Clinically Significant Errors in AI Notes" (Biro 2025, Anderson 2025) → CM-09; "Negation Errors" (Bundy 2024) → CM-09; RDoC/PHQ-9 documentation level (Castro 2025) → CM-08; "Likelihood of Psychiatric Intervention, aOR" (Castro 2025) → quality-of-care/clinical-decision-rate, adjacent to but not itself safety.
  • Suki's own evidence-linking and note-accuracy work (CM-09's H15/source_transcripts[]) will generate data that looks safety-relevant but should be reported under CM-09/CM-08 unless paired with an observed clinical action or harm signal.
  • H8 and H11 are the relevant future hooks for CM-19, not H1. Any CM-19 evaluation plan should be scoped against H8/H11 deployment timelines, not current production capability.
  • Pearlman/Castro-style aOR findings cut both directions. A significant aOR (e.g., Castro 2025's 0.83, p=.005 — more documentation, less intervention) is a potential unintended consequence, not automatically "bad" without further investigation — but it is the kind of signal CM-19 needs.

NB — Net Benefits Patient Volume Also known as: Encounters per Provider per Week  ·  Patient Throughput  ·  Volume Capacity

Unit

Unit

↑ Higher is better

A completed encounter is a patient visit that has a signed clinical note in the EHR. Encounters are counted per provider per clinical week and normalized to each provider's scheduled clinical hours to account for part-time work. The metric captures whether providers can see more patients as documentation burden decreases after Suki adoption.

Gold Standard
Completed, signed encounters from the EHR, normalized to scheduled clinical hours per week. Preferred — captures realized patient throughput and controls for part-time schedules.
Default / Practical
Scheduled encounters per week (from the EHR schedule), when completion and signing status are unavailable. Use with caution — scheduled volume does not equal completed volume and may not reflect the documentation-driven capacity effect.
⚠ Ambiguities to Resolve
  • Normalize for scheduled clinical hours. A provider who reduces from 5 to 4 clinical days will show a raw encounter drop unrelated to Suki. Divide by scheduled hours or clinical days to compute a rate; compare rates, not raw counts.
  • Exclude providers who changed practice context. Providers who changed specialty, site, or panel size during the analysis window introduce confounders that are unrelated to Suki adoption. Exclude these providers or analyze them separately.
  • Only include completed, signed encounters. Scheduled-but-not-completed visits (no-shows, cancellations) and encounters without a signed note should be excluded. Mixing completion statuses inflates raw counts and obscures the capacity signal.
Interpretation caution: Increased encounter volume is not universally desirable. CM-23 — Implementation Barriers and Workflow Fit

SerQ — Service Quality Implementation & Workflow Fit Also known as: Implementation Barriers  ·  Learning Curve  ·  Workflow Adaptation

Unit

Unit
FIM/AIM/IAM composite implementation-outcome score (1–5) + qualitative barrier theme frequency
↑ Higher fit / fewer barriers is better

Factors that impede or facilitate ambient AI scribe adoption and sustained use, including technical barriers, workflow integration challenges, specialty fit, training quality, and organizational support. Mapped to the Service Quality (SerQ) dimension as a property of the deployment/implementation experience, distinct from the tool's own usability (CM-15) or the provider's stated intention to keep using it (CM-14). This measure uniquely combines a validated quantitative implementation-outcome scale with a qualitative barrier-coding component — neither is sufficient alone.

Gold Standard
Feasibility of Intervention Measure (FIM) / Acceptability of Intervention Measure (AIM) / Intervention Appropriateness Measure (IAM) — each a 4-item, 1–5 Likert scale (Weiner et al. 2017), reported in the corpus via Suhail 2026.
Default / Practical
Structured qualitative-mixed-methods assessment against an implementation-science framework (CFIR, RE-AIM, or SEIPS 3.0) plus non-adopter category analysis — the pattern used by most of the 12 corpus papers, since only one names a formally scored instrument.
⚠ Ambiguities to Resolve
  • FIM/AIM/IAM sourcing is itself flagged as unverified in the underlying literature review. The corpus notes state: "unclear where Suhail 2026 is sourcing FIM/AIM/IUS from, check that these scales appear in the paper and are correctly attributed." Do not treat this instrument as confirmed corpus-validated until independently verified against the primary source.
  • "IUS" is an undefined acronym in the source material — possibly a typo for IAM, or a distinct scale. Unresolved; do not field an "IUS" instrument without first clarifying what it refers to.
  • Heterogeneous frameworks are not interchangeable. RE-AIM, CFIR, SEIPS 3.0, and QUEST are structurally different mixed-methods frameworks, not alternate scoring systems for the same number. Pick one framework per deployment and hold it constant across administration waves.
  • Non-adopter survivorship bias. Providers who fully disengage from Suki are also the least likely to respond to any follow-up survey, biasing barrier data toward moderate/partial users rather than true non-adopters — the group implementation barriers matter most for.
  • No standardized qualitative barrier taxonomy exists in the corpus. AAFP 2021 uses 4 non-adopter types, PHTI 2025 uses 3 adoption cohorts, and other papers use free-form thematic analysis. Any dashboard-level "top barriers" frequency count requires establishing a project-specific coding taxonomy first.

CM-24 — Transcription and ASR Accuracy

SQ — System Quality ASR / Transcription Quality ⚠ No Suki Data Source Available Also known as: Word Error Rate (WER)  ·  ASR Accuracy  ·  Medical Term Recall (MTR)  ·  Speaker Diarization Accuracy

Unit

Unit
Word Error Rate (%) — with Speaker Diarization Accuracy (%) as companion metric
↓ Lower WER is better

Word Error Rate (WER) is the percentage of words in an ASR-generated transcript that are incorrect relative to a human-transcribed reference, computed via minimum edit distance (substitutions + deletions + insertions) divided by total reference words. Speaker Diarization Accuracy is the percentage of transcript segments correctly attributed to the correct speaker (clinician vs. patient) and is reported alongside WER as this measure’s companion metric — both describe the technical fidelity of the raw transcript that every downstream note is built on.

This is the upstream quality gate: if the transcript is wrong, the generated note will be wrong regardless of how good the summarization/NLP layer is. It is a distinct measurement point from CM-08/CM-09/CM-10/CM-12 (note-level quality), which score the note, not the transcript that fed it.

Gold Standard
Human-transcribed reference transcript, produced by a professional medical transcriptionist blind to the ASR output, aligned word-by-word against the ASR hypothesis using standard edit-distance tooling (e.g., NIST sclite, jiwer).
Default / Practical
None established. No fallback or proxy WER methodology is published in the corpus or in any commercial ambient-AI vendor’s public documentation, Suki included — see Data Requirements below.
⚠ Ambiguities to Resolve
  • No data source is currently available to populate this measure. Per the literature review’s Key Note: no commercial ambient-AI vendor — Suki included — publishes WER or diarization accuracy figures. This is a documented industry-wide opacity pattern dating to van Buchem 2021, not a Suki-specific gap. As of this writing there is no reference transcript, ASR decoder/confidence output, or third-party WER benchmark accessible for Suki sessions, so this measure cannot currently be computed on Suki data (see Data Requirements and Suki Data Scope below).
  • Only 3 papers in the entire corpus measure this directly (Anderson 2025 simulation; Wang 2025 evaluation framework; van Buchem 2021 scoping review) — the published evidence base for expected WER/diarization ranges in ambient clinical scribes generally, not just for Suki, is thin.
  • Upstream/downstream conflation risk. ASR errors propagate into note-quality measures (CM-08, CM-09, CM-10, CM-12) with no way to isolate how much of a note-level error originated in the transcript versus downstream summarization — without WER data, Transcript Error Transmission Rate (Anderson 2025) also cannot be computed.
  • Word-level scoring is itself ambiguous for clinical speech. Medical terminology, abbreviations, and multi-speaker crosstalk complicate standard WER alignment; Wang 2025’s Medical Term Recall (MTR) submetric exists specifically because generic WER under- or over-penalizes clinical-vocabulary errors depending on tokenization choices. A fixed alignment/tokenization protocol would need to be chosen before any number is reported.

Unit

Unit
Study-rigor profile — Inter-rater reliability (ICC) + Evidence-design tier

A composite indicator of how trustworthy a given published study’s measurement approach is — combining (a) inter-rater reliability, typically the Intraclass Correlation Coefficient (ICC) or RWG agreement statistic among independent human/LLM raters, and (b) an evidence-design tier ranking the study’s methodological rigor (e.g., RCT > propensity-matched observational > pre-post QI study with no control).

Algorithm

1 Study Rigor Profile — ICC + Evidence-Design Tier Applied to literature-review source papers, not to Suki sessions

Scores a source paper’s methodological trustworthiness on two independent axes: statistical agreement among the paper’s own raters (ICC), and a design-tier ranking of the study’s overall rigor. Used internally to weight how much confidence to place in a paper’s reported effect sizes when synthesizing across the literature-review corpus — it is not computed from any Suki product or clinical data.

Units in this Algorithm
Primary
Inter-rater reliability (ICC)
Continuous 0–1 statistic, computed per source paper across its own reported independent raters (human and/or LLM-as-judge). Not reported by every paper — only those that used multi-rater scoring.
Secondary
Evidence-design tier
Ordinal ranking of the study’s design (RCT > propensity-matched observational > pre-post QI, no control > case report / simulation-only), assigned during literature-review coding.
⚠ Tier assignment is a human-review judgment call for borderline designs (e.g., a QI study with partial matching) — not a mechanical function of reported keywords.
Secondary
Cross-replicate consistency
Where reported (e.g., Kernberg 2023: 53%), the stability of a paper’s measures across repeated model runs on the same input — an additional rigor signal specific to papers evaluating LLM-generated content.
ICC (two-way random)=Between-Rater VarianceBetween-Rater Variance + Within-Rater (Residual) Variance
Standard two-way random-effects ICC (Shrout & Fleiss 1979 / McGraw & Wong 1996 form) Computed per source paper, across that paper's own reported raters Reporting grain: one ICC value (where available) + one evidence-tier label, per source paper
Pseudocode — Rigor Profile Assembly (mechanics only, not a combined score)
for paper P in corpus: # Component 1: inter-rater reliability (only if P reports independent raters) if P.reports_multi_rater_scores: icc[P] = ICC_TWO_WAY_RANDOM(P.rater_scores) # or RWG, if P used a within-group agreement design else: icc[P] = NOT_REPORTED # Component 2: evidence-design tier (human-assigned during literature-review coding) tier[P] = CASE WHEN P.design == "RCT" (incl. stepped-wedge) THEN 1 # highest rigor WHEN P.design == "propensity-matched observational" THEN 2 WHEN P.design == "pre-post QI, no control" THEN 3 WHEN P.design IN ("case report", "simulation-only") THEN 4 # lowest rigor ELSE tier[P] = REQUIRES_HUMAN_REVIEW # ambiguous design # Component 3 (where reported): cross-replicate consistency consistency[P] = P.cross_replicate_consistency_pct OR NOT_REPORTED # This algorithm deliberately does NOT auto-combine these into one number. # Per the Key Note above, the human research team reviews the profile as a whole. rigor_profile[P] = { icc: icc[P], design_tier: tier[P], cross_replicate: consistency[P] }
