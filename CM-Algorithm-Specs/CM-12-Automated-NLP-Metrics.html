Canonical Measure Algorithm Card

CM-12 — Automated NLP Evaluation Metrics

IQ — Information Quality Methodological / Calibration Tool Also known as: ROUGE Score  ·  BERTScore  ·  BLEURT  ·  F1 Score  ·  SAIL Score  ·  LLM-as-Evaluator Agreement

Unit

Unit
Automated similarity score (ROUGE-L, BERTScore F1, or token-level F1) between AI note and a reference note
↑ Higher = closer match to reference

This is a methodological measure, not a clinical outcome. CM-12 computes n-gram overlap (ROUGE), semantic similarity (BERTScore/BLEURT), or token-level precision/recall (F1) between an AI-generated note and a reference note. It does not assess Suki's documentation quality directly — it assesses whether an automated evaluation method (used to scale up CM-08/CM-09/CM-10 scoring) agrees closely enough with human judgment to be trusted.

Concretely: CM-12 is the correlation-validation step that answers "how do we know our LLM-as-judge pipeline for CM-08/CM-09/CM-10 is trustworthy?" — it is a calibration check for other measures' evaluation pipelines, not a longitudinal outcome measure of Suki's performance. See Expected Trend below.

Gold Standard
BERTScore / entity-level F1 — embedding-based semantic similarity, captures paraphrase-level overlap rather than exact wording, generally considered a stronger candidate for clinical text than raw n-gram overlap.
Default / Practical
ROUGE-1/2/L — n-gram overlap, cheap to compute, the most widely reported baseline in this literature. Per Moramarco 2022, a naive Levenshtein (edit) distance baseline performs comparably to BERTScore on clinical notes — metric choice should be validated per use case, not assumed from general-domain NLP benchmarks.
⚠ Ambiguities to Resolve
  • Expensive metrics may not earn their keep. Moramarco 2022's central finding: Levenshtein distance performs as well as BERTScore on clinical notes. Before committing to an embedding-based metric pipeline, benchmark it against a cheap edit-distance baseline on the specific note types in scope.
  • A high automated score does not certify clinical quality. Per the corpus Key Note, these are research tools, not clinical quality measures — a high ROUGE/BERTScore/F1 says the AI note textually resembles the reference, not that it is clinically accurate (CM-09) or complete (CM-08) on its own.
  • Requires a trusted reference note. Every variant of this metric needs a physician-authored or otherwise-trusted comparison note per encounter — the same reference-availability constraint noted for CM-11's note-length-ratio variant.
  • No fixed acceptability threshold exists in this corpus. Thresholds for "acceptable" ROUGE/BERTScore/F1 in clinical documentation must be locally calibrated against the human/LLM-judge ratings from the CM-08/09/10 pilots — general-domain NLP benchmarks (e.g., news summarization) do not transfer.

Algorithm

1 Correlation-Validation Step — Automated Metric vs. Human/LLM-Judge Agreement Calibration check for the CM-08/09/10 pipeline — not a standalone outcome

For the same sample already scored by physician raters and an LLM-as-judge during the CM-08/CM-09/CM-10 pilot, compute one or more automated NLP metrics on the same note/ reference pairs and correlate each metric against the human/LLM-judge composite score. This establishes whether a given automated metric is trustworthy enough to supplement or pre-screen for the rating pipeline at scale — it is a tool-validation step, not a measure of Suki's clinical performance in its own right.

Units in this Algorithm
Primary
Automated metric score (ROUGE-L / BERTScore F1 / token F1 — select per pilot), 0–1 scale
Computed per note/reference pair for every candidate metric under evaluation. Not reported as a standalone dashboard value — only meaningful in relation to its correlation with human ratings, below.
Secondary
Reference note (physician-authored or trusted comparison note)
The comparison text every candidate metric is scored against.
⚠ Same reference-availability constraint as CM-11's note-length-ratio variant — often unavailable outside simulation/RCT designs or once EHR final-note access exists.
Secondary
Metric-to-human correlation (r)
Pearson/Spearman correlation between the automated metric score and the human-rater / LLM-judge composite score (from CM-08/09/10) on the same sample. The gating value for whether the automated metric can be trusted as a scaling/screening signal for those measures.
⚠ Scope reminder: this algorithm validates an evaluation tool, not Suki's documentation quality. A high metric-to-human correlation means the automated metric can be trusted as a scaling signal for CM-08/09/10 — it says nothing about the AI note's accuracy or completeness on its own.
Metric Validity (r)= CORRELATION(automated_metric_score, human/LLM-judge composite score) [per candidate metric, per calibration sample]
Calibration design: 1. Reuse the CM-08/09/10 pilot sample (same note/reference pairs already scored by raters + LLM-judge) 2. Compute each candidate automated metric (Levenshtein, ROUGE-1/2/L, BERTScore, token F1) on the same pairs 3. Correlate each candidate metric against the human/LLM-judge composite score 4. Approve any metric with r >= threshold (locally calibrated, no universal cutoff) as a scaling/screening signal 5. Re-run whenever the note-generation model version changes, or the CM-08/09/10 sample is refreshed Reporting cadence: one-time or periodic recalibration -- NOT a continuously tracked operational metric. No pre/post Suki-adoption trend applies to this measure.
Pseudocode
calibration_sample = CM_08_09_10_pilot_sample # reuse, do not re-collect CANDIDATE_METRICS = ["levenshtein", "rouge1", "rouge2", "rougeL", "bertscore", "token_f1"] for pair in calibration_sample: reference = pair.reference_note # physician-authored or trusted comparison note note = pair.generated_note human_score = pair.human_llm_judge_composite_score # already computed for CM-08/09/10 for metric in CANDIDATE_METRICS: metric_score[metric][pair] = COMPUTE_METRIC(metric, note, reference) for metric in CANDIDATE_METRICS: agreement_r[metric] = CORRELATION( [metric_score[metric][p] for p in calibration_sample], [p.human_llm_judge_composite_score for p in calibration_sample] ) approved_metrics = [m for m in CANDIDATE_METRICS if agreement_r[m] >= LOCAL_THRESHOLD] dashboard_value = { "agreement_r_by_metric": agreement_r, "approved_metrics": approved_metrics } # Re-run this entire calibration when the note-generation model version changes, # or when the CM-08/09/10 pilot sample is refreshed -- not on a recurring monitoring cadence.
Metric-to-Human Agreement by Method — No Pre/Post Trend Applies

No pre/post Suki-adoption trend applies to this measure. CM-12 is a one-time or periodically-repeated calibration check across candidate automated metrics, not a longitudinal outcome — there is nothing analogous to "before Suki" and "after Suki" for a tool-validation step. Suki Data — Scoped Role

Suki's note content and transcript endpoints supply the AI-note side of every metric computation. Suki has no native reference-note store and does not compute ROUGE/BERTScore/F1 itself — metric computation, and the correlation step against human ratings, happen entirely outside Suki, at the evaluation-pipeline level.

CM-12 is fully dependent on the CM-08/CM-09/CM-10 rating pipeline having already run: it reuses that pilot's note/reference pairs and human/LLM-judge scores rather than collecting new ones. It should be treated as a validation add-on to those measures' pipelines, not a standalone data-collection effort.
