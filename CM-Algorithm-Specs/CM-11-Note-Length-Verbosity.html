Canonical Measure Algorithm Card

CM-11 — Note Length and Verbosity

IQ — Information Quality Automated NLP Text Metric Also known as: Note Length  ·  Word Count  ·  Lexical Diversity  ·  Documentation Length

Unit

Unit
Words (or characters) per note; secondary: lexical diversity (type-token ratio)
↕ Direction not asserted — context-dependent

The length and lexical richness of an AI-generated note, measured as word count, character count, or lexical diversity (unique vocabulary / total words). Unlike CM-08, CM-09, and CM-10, this unit is fully automated — it can be computed directly from note text without a human or LLM rater, using either Suki-native note content or, if accessible, EHR note-text fields.

Note length is a secondary / proxy measure, not a quality measure in its own right. Longer notes can indicate greater thoroughness (fewer omissions, see CM-08) or over-generation and padding that increases physician editing burden (Wojda 2025, Shah 2025 flag verbosity as a specific concern). This card does not assert which interpretation applies — see the Expected Trend section below.

Gold Standard
Word count (tokenized, whitespace/punctuation-normalized) per note — the most directly comparable operationalization across papers and across note templates, since it is less sensitive to formatting than raw character count.
Default / Practical
Character count per note or per calendar week — often the only granularity available from EHR-side documentation-length telemetry (chars/week) when word-level tokenization access is not available.
⚠ Ambiguities to Resolve
  • Direction is genuinely ambiguous. Unlike every other measure in this batch, there is no single expected direction after Suki adoption. Longer notes may reflect improved thoroughness (which should co-occur with a falling CM-08 omission rate) or increased padding/over-generation (which physicians report as added editing burden). CM-11 should always be interpreted alongside CM-08 (Completeness) and CM-10 (Overall Quality) — never read as a standalone quality signal in either direction.
  • Word count, character count, and note-length ratio are not interchangeable. Note length ratio (AI note length / human-authored note length) requires a human-authored reference note for the same encounter, which may not exist in AI-first documentation workflows.
  • Lexical diversity is length-sensitive. Type-token ratio is mechanically higher for shorter notes; comparing raw TTR across notes of different lengths requires a length-normalization method (e.g., MTLD or a fixed-window TTR), not a raw ratio.

Algorithm

1 Automated Text-Metric Computation — Note Length & Lexical Diversity Fully automated — no rater pipeline required

Computed directly from note text for every completed session — word count, character count, and lexical diversity require no human or LLM rating step, unlike CM-08, CM-09, and CM-10. The output is a distribution (not a single pass/fail value) reported alongside CM-08 and CM-10 so a length change can be interpreted rather than read in isolation.

Units in this Algorithm
Primary
Word count per note (tokenized)
Total tokens in the generated note after whitespace/punctuation normalization. Reported as a cohort mean and full distribution per period.
Secondary
Character count per note
Total characters in the generated note. Used when word-level tokenization is unavailable, e.g. for EHR-side documentation-length telemetry reported as characters/week.
⚠ Sensitive to note template/formatting (headers, structured fields) — less portable across EHR templates than word count.
Secondary
Lexical diversity (type-token ratio)
Unique word count / total word count per note, as a secondary richness signal alongside raw length.
⚠ Length-sensitive — requires normalization (MTLD or fixed-window TTR) before comparing notes of different lengths.
Secondary
Note length ratio (AI note / human-authored reference note)
Ratio of AI note length to a human-authored comparison note for the same encounter, where available (e.g., simulation or RCT designs with a paired human note).
⚠ Requires a human-authored reference note per encounter — often unavailable outside controlled study designs.
Mean Note Length=∑ (word count per note, in the period)COUNT(notes in the period)
Reporting grain: cohort mean and full distribution, per month No single pass/fail threshold is applied to the mean or distribution. Flag only statistical outliers (e.g., notes >2 SD from the cohort mean) for manual review -- outliers may indicate either exceptional thoroughness or malfunctioning generation, not a length target to hit. Always report alongside CM-08 (Completeness) and CM-10 (Overall Quality) in the same period, so a length change can be interpreted rather than read as good or bad on its own.
Pseudocode
for session in all_completed_sessions: note_text = session.note_content word_count[session] = COUNT(TOKENIZE(note_text)) char_count[session] = LENGTH(note_text) unique_words = COUNT(DISTINCT TOKENIZE(note_text))) lexical_diversity[session] = unique_words / word_count[session] # raw TTR, needs normalization lexical_diversity_normalized[session] = MTLD(TOKENIZE(note_text)) # length-independent variant if human_reference_note[session] exists: length_ratio[session] = word_count[session] / COUNT(TOKENIZE(human_reference_note[session])) mean_word_count = MEAN(word_count[s] for s in all_completed_sessions in period) distribution = HISTOGRAM(word_count.values()) outliers = [s for s in all_completed_sessions if ABS(word_count[s] - mean_word_count) > 2 * STDDEV(word_count.values())] dashboard_value = { "mean_word_count": mean_word_count, "distribution": distribution, "mean_lexical_diversity_normalized": MEAN(lexical_diversity_normalized.values()), "outlier_sessions": outliers } # No pass/fail evaluation here -- read alongside CM-08 and CM-10 for interpretation
Expected Trend — Note Length: No Single Direction Assumed

Unlike every other measure in this batch, CM-11 does not assume a single expected direction after Suki adoption. A post-adoption change in mean note length is consistent with two opposite interpretations, and this card intentionally does not pick one: Scenario A — length increases alongside improved thoroughness (would co-occur with a falling CM-08 omission rate); Scenario B — length settles or falls as generation is tuned to avoid padding (would co-occur with a stable or rising CM-10 composite score). Read this chart together with CM-08 and CM-10 for the same period, never alone.

Suki Data — Scoped Role

Suki's generated note content is sufficient on its own to compute CM-11's primary unit. Word count, character count, and lexical diversity require no rater pipeline and no EHR access — they can be computed for every completed session directly from GET /session/{id}/content.

EHR-side note text would extend this measure to the physician-accepted final note rather than just the Suki draft, and would support the note-length-ratio variant against a human-authored reference note where one exists. Verified against Epic's real EHI schema: HNO_NOTE_TEXT (the reporting-grade table per Epic's own docs) is not present in this EHI export snapshot; HNO_PLAIN_TEXT is the closest table actually available but only covers plain-text notes (excludes rich-text notes), so length/diversity computed from it would understate coverage for any org with meaningful rich-text note volume. Neither addition is required to compute the primary unit today; they refine the reference point, not the computability of the measure.
