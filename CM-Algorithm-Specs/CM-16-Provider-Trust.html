Canonical Measure Algorithm Card

CM-16 — Provider Trust in AI

U — Use Trust & Reliability Also known as: Trust in AI  ·  Provider Skepticism  ·  Accuracy Confidence

Unit

Unit
Trust-in-AI Likert score (1–5, provisional anchor)
↑ Higher is better

The degree to which clinicians perceive AI-generated documentation as accurate and dependable enough to act on without exhaustive verification. This is an attitudinal precondition that shapes adoption before and during use: a clinician who doubts output accuracy will either reject the tool or spend significant time re-checking every note, negating efficiency gains. Placed in the Use (U) dimension rather than User Satisfaction (US) because it precedes adoption rather than resulting from it. Distinct from general satisfaction (CM-15, overall experience after use) and from adoption behavior (CM-13, what clinicians actually do).

Gold Standard
A direct single-item "Trust in AI" Likert rating administered as part of a controlled study, per Afshar 2025b (reported as a secondary RCT outcome) — the only quantitative instance of this construct in the corpus.
Default / Practical
Qualitative thematic coding of verification behavior, hesitation, and skepticism from semi-structured interviews (Shah 2025, Wojda 2025). Given that 2 of the 3 papers measuring this construct are qualitative, this is the more commonly available operationalization in practice.
⚠ Ambiguities to Resolve
  • Sparse quantitative coverage. Only 3 papers in the corpus formally measure this as a study outcome, and 2 of the 3 are qualitative. No paper reports a validated multi-item trust instrument with published psychometrics — the 1–5 anchor above is a provisional convention, not corpus-confirmed.
  • No true pre-exposure baseline for tool-specific trust. Trust in this specific tool cannot be rated before any use. The Phase 0 wave below should be understood as generalized/dispositional trust in AI documentation tools broadly, not trust in Suki specifically — a related but distinct precursor construct.
  • Overreliance confound. A high trust score alone does not distinguish appropriate confidence from unsafe over-reliance (automation bias). This measure should not be reported as a safety signal on its own — pairing with a verification-behavior or error-detection measure is a scope boundary with CM-19 (Clinical Patient Safety), not something CM-16 resolves by itself.
  • Qualitative-to-quantitative comparability. Verification-behavior and skepticism themes from interviews (Shah 2025, Wojda 2025) are not directly poolable with the Likert item from Afshar 2025b without a coding rubric that maps themes to an ordinal trust proxy.

Algorithm

1 Survey Instrument Scoring — Dose-Response Cohort Comparison Dispositional / experience-based administration

Produces a cohort-level trust score for each administration wave, compared across Suki utilization tiers, and paired with a qualitative verification-behavior theme code as a companion signal (not merged into the numeric score). The quantitative score is expected to increase from generalized/dispositional trust (Phase 0) to experience-based trust in Suki specifically (Phase 3), most in the heaviest-utilization cohort.

Units in this Algorithm
Primary
Trust-in-AI Likert score (1–5)
The canonical unit for this measure — defined in the Unit card above. Computed as the mean of the administered trust item(s) per respondent per wave, then averaged within each utilization-tier cohort.
⚠ Item wording and anchor are provisional given the thin quantitative base — see Ambiguities above.
Secondary
Suki utilization tier (heavy / moderate / light)
Per the PHTI 2025 framework: heavy (≥70% of eligible encounters with a completed Suki session), moderate (30–69%), light (<30%), assigned per provider by week 4 of adoption and held fixed for the comparison window.
Secondary
Verification-behavior / skepticism theme code (qualitative)
Thematic code (e.g., "always re-checks," "spot-checks," "rarely verifies") assigned from interview transcripts, reported alongside — not averaged into — the quantitative score.
⚠ No standardized coding rubric exists in the corpus; establish a project-specific taxonomy before coding, and do not pool with the Likert score.

Pseudocode
Phase 0 (T0, at/before go-live, all eligible providers): score[p, T0] = MEAN(trust item responses, 1-5) for provider p # measures generalized/dispositional trust in AI documentation tools, not Suki specifically Weeks 1-16: track Suki sessions per provider per week utilization_pct[p] = completed sessions / eligible encounters (rolling 4-week) tier[p] = HEAVY if utilization_pct[p] >= 0.70 MODERATE if 0.30 <= utilization_pct[p] < 0.70 LIGHT if utilization_pct[p] < 0.30 (assigned at week 4, held fixed) Phase 3 (T3, months 4-9, same respondents where possible): score[p, T3] = MEAN(trust item responses, 1-5) for provider p # now Suki-specific theme_code[p, T3] = CODE_INTERVIEW(transcript[p]) # qualitative, reported separately For each tier T in {HEAVY, MODERATE, LIGHT}: cohort_score[T, T0] = MEAN(score[p, T0] for p in tier T) cohort_score[T, T3] = MEAN(score[p, T3] for p in tier T) dose_response_delta[T] = cohort_score[T, T3] - cohort_score[T, T0] theme_distribution[T] = FREQUENCY(theme_code[p, T3] for p in tier T) dashboard_value = dose_response_delta[HEAVY] vs dose_response_delta[LIGHT] (report alongside theme_distribution[T], not merged into it)
Expected Trend — Trust-in-AI Score / Cohort / Wave

Cohort-mean trust score is projected to increase from generalized/dispositional trust (Phase 0) to Suki-specific, experience-based trust (Phase 3), most in the heavy-utilization cohort. Only 3 papers in this corpus formally measure trust as a study outcome (1 quantitative, 2 qualitative), so this dose-response shape is a plausible projection, not a corpus-replicated finding.

Suki Data — Scoped Role

Suki's role for CM-16 is limited to utilization-cohort scaffolding. Session counts and timing define the heavy/moderate/light dose-response cohorts used to compare trust trajectories. Suki has no native trust, skepticism, or verification-behavior signal — this is an attitudinal construct with no API analog, and the platform cannot observe whether a clinician re-checked or accepted a note without independent verification.

The Trust-in-AI Likert item(s) and verification-behavior interviews must be administered and captured by the customer or research team, on the schedule above. Given the thin quantitative evidence base (1 of 3 corpus papers), any Suki-sponsored fielding of this measure should be treated as exploratory rather than a replication of an established finding.
