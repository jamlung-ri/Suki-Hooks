Canonical Measure Algorithm Card

CM-01 — Clinician Burnout and Exhaustion

NB — Net Benefits Provider Wellbeing Also known as: Work Exhaustion  ·  Emotional Exhaustion  ·  Burnout Syndrome

Unit

Unit
PFI Work Exhaustion subscale score (1–5)
↓ Lower is better

Provider-reported emotional exhaustion, depersonalization, and interpersonal disengagement from clinical work — the core burnout syndrome — measured via a validated psychometric instrument administered at defined intervals around Suki adoption. Distinct from in-encounter cognitive load (CM-02) and professional fulfillment (CM-03), which are adjacent but dissociable constructs.

Gold Standard
Stanford Professional Fulfillment Index (PFI), Work Exhaustion subscale — 10-item, 1–5 scale (higher = worse). The instrument used in the strongest external RCT (Afshar 2025b, n=66), which found a −0.44 reduction.
Default / Practical
Mini-Z / Mini-Z 2.0 — 10-item brief burnout screen, 10–50 scale (higher = better, opposite polarity from PFI). Lower respondent burden; widely used in quality-improvement contexts and proposed as the Phase 0/Phase 3 instrument.
⚠ Ambiguities to Resolve
  • The baseline problem. A true pre/post comparison requires a baseline survey administered before Suki go-live. If Suki is engaged retrospectively, this window is permanently lost — CM-01 then can only be measured as a cohort-level dose-response comparison (heavy vs. light users at follow-up), not an individual-level pre/post change.
  • Self-report inflation. Self-report-only studies (Shah 2024: −1.94 on the PFI Work Exhaustion subscale) substantially overstate effect size relative to the RCT (Afshar 2025b: −0.44) — a gap expected from volunteer/selection bias in non-randomized designs. Do not present self-report-only deltas as equivalent to RCT effect sizes.
  • Instrument-direction mismatch. PFI Work Exhaustion is 1–5 where higher = worse; Mini-Z is 10–50 where higher = better. If a site switches instruments between baseline and follow-up, scores must be normalized to a common direction before any comparison is made.
  • Individual-level linkage vs. anonymity. Linking a provider's baseline survey response to their post-deployment utilization tier requires either non-anonymous administration (reduces candor on a sensitive topic) or a study-specific pseudonymous code maintained outside Suki.

Algorithm

1 Survey Instrument Scoring — Dose-Response Cohort Comparison Phase 0 / Phase 3 administration

Produces a cohort-level burnout score for each administration wave, compared across Suki utilization tiers rather than (or in addition to) a simple pre/post pooled comparison. The score is expected to decrease (PFI scale) after Suki adoption, with the largest decrease in the heaviest-utilization cohort.

Units in this Algorithm
Primary
PFI Work Exhaustion subscale score (1–5)
The canonical unit for this measure — defined in the Unit card above. Computed as the mean of the 10 subscale items per respondent per administration wave, then averaged within each utilization-tier cohort.
Secondary
Suki utilization tier (heavy / moderate / light)
Per the PHTI 2025 framework: heavy (≥70% of eligible encounters with a completed Suki session), moderate (30–69%), light (<30%), assigned per provider by week 4 of adoption and held fixed for the comparison window.
⚠ Tier assignment is the only place Suki contributes primary data to this algorithm. Without a pre-deployment baseline, the comparison is heavy-vs-light at follow-up, not within-provider change.
Subscale Score=∑ (item response, 1–5) across 10 items10
Administration: Phase 0 (pre-deployment baseline, 4 weeks before go-live) — Phase 3 (months 4–9 follow-up) Cohort: heavy / moderate / light Suki utilization tier, assigned at week 4 of adoption Reporting: cohort-mean subscale score per wave; report dose-response delta (heavy minus light), not just pooled pre/post Corroboration: report alongside after-hours/pajama-time delta where EHR audit-log data is available
Pseudocode
Phase 0 (T0, pre-deployment, all eligible providers): score[p, T0] = MEAN(PFI Work Exhaustion items 1..10) for provider p Weeks 1-16: track Suki sessions per provider per week utilization_pct[p] = completed sessions / eligible encounters (rolling 4-week) tier[p] = HEAVY if utilization_pct[p] >= 0.70 MODERATE if 0.30 <= utilization_pct[p] < 0.70 LIGHT if utilization_pct[p] < 0.30 (assigned at week 4, held fixed) Phase 3 (T3, months 4-9, same respondents where possible): score[p, T3] = MEAN(PFI Work Exhaustion items 1..10) for provider p For each tier T in {HEAVY, MODERATE, LIGHT}: cohort_score[T, T0] = MEAN(score[p, T0] for p in tier T) cohort_score[T, T3] = MEAN(score[p, T3] for p in tier T) dose_response_delta[T] = cohort_score[T, T3] - cohort_score[T, T0] dashboard_value = dose_response_delta[HEAVY] vs dose_response_delta[LIGHT] (expect HEAVY delta more negative than LIGHT delta, on the PFI 1-5 scale)
Expected Trend — PFI Work Exhaustion Score / Cohort / Wave

Cohort-mean PFI Work Exhaustion score should decrease from Phase 0 (pre-deployment baseline) to Phase 3 (months 4–9), with the heavy-utilization cohort showing the largest decline (dose-response). Literature anchor: Afshar 2025b RCT, −0.44 (objective gold standard); self-report-only designs (Shah 2024, −1.94) substantially overstate this effect.

Data Requirements

Data Element Description Source Notes
PFI Work Exhaustion subscale responses (Phase 0) 10-item, 1–5 scale, administered to all eligible providers 4 weeks before Suki go-live. The single most time-sensitive data element — permanently unavailable if missed. Survey Administered by customer or research team; Suki has no in-app distribution mechanism.
PFI Work Exhaustion subscale responses (Phase 3) Same instrument, administered months 4–9 post go-live to the same respondent pool where possible. Survey Alternative: Mini-Z / Mini-Z 2.0 (10–50 scale, higher = better) if lower respondent burden is required — note the direction reversal.
Sessions per provider per week Completed Suki session counts, used to compute rolling utilization percentage and assign heavy/moderate/light tier at week 4. Suki GET /session/{id}/status (aggregated). Defines the independent variable for the dose-response design.
Session status distribution completed vs. skipped vs. failed rate per provider — an adoption-quality covariate; high skip/fail rates plausibly track frustration, a burnout precursor. Suki GET /session/{id}/status.
Session-timing distribution (business hours) % of a provider's sessions started outside a defined business-hours window — a rough Suki-native proxy for after-hours documentation activity (a mechanism, not the outcome). Suki Derived from GET /session/{id}/transcript start/end timestamps.
After-hours / "pajama time" EHR active time Objective correlate of the documentation-burden pathway believed to drive burnout reduction. Reported alongside the survey delta as mechanism-level corroboration. EHR Epic Signal "Time Outside Scheduled Hours" / "Pajama Time," or vendor equivalent.
Provider schedule / specialty / FTE status Defines the business-hours window for classifying session timestamps and EHR activity; used to stratify and exclude part-time or non-clinical staff. EHR EHR scheduling module and provider directory.
Suki adoption date Date of each provider's first completed Suki session. Anchors the utilization-tier tracking window. Suki Does not itself define a pre/post split for CM-01 — the Phase 0 survey must precede this date.

Suki Data — Scoped Role

Suki's role for CM-01 is limited to adoption-boundary and utilization-cohort scaffolding. Session counts and timing define the heavy/moderate/light dose-response cohorts, and session-timing distribution provides a rough proxy for after-hours activity. Suki has no native survey-response or rating data for this measure — burnout itself is a provider-reported psychological construct with no API analog.

The PFI Work Exhaustion (or Mini-Z) survey must be administered and captured by the customer or research team, on the schedule above. Without a pre-deployment (Phase 0) baseline, CM-01 can only be reported as a cohort-level dose-response comparison at follow-up, not an individual-level pre/post change.
