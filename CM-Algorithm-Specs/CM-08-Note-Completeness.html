Canonical Measure Algorithm Card

CM-08 — Note Completeness and Omission Rate

IQ — Information Quality Pilot / Calibration Design Also known as: Omissions  ·  Omission Errors (%)  ·  Thoroughness (PDQI domain)  ·  Completeness

Unit

Unit
% of notes with ≥1 clinically relevant element omitted (below Thoroughness threshold)
↓ Lower is better

The absence of clinically relevant information from an AI-generated note — content that was present in the encounter (or in a reference note) but does not appear anywhere in the generated note. Distinct from CM-09 (Note Inaccuracy Rate), which measures content that is present but wrong. Omissions are the dominant error type in ambient documentation: all 5 simulation studies in this corpus that categorize error types find omissions account for 71–86% of all errors, making completeness the single most consistent Information Quality finding in the literature.

Gold Standard
PDQI-9 / PDSQI-9 Thoroughness domain — 5-point Likert subscale scored by physician raters against a reference (transcript or physician-authored note). PDSQI-9 is the AI-note-adapted version; the same LLM-as-judge validation pattern used for CM-09's Accuracy domain (Afshar 2025b) applies to Thoroughness.
Default / Practical
Reference-checklist coverage check using Suki's source_transcripts[] evidence-linking primitive in reverse — flags transcript-evidenced clinical elements that have no corresponding sentence anywhere in the generated note. Used as a pre-screening signal and sampling frame for the rating pipeline.
⚠ Ambiguities to Resolve
  • The Missing Feedback Loop (shared with CM-09). Suki never sees the physician's post-generation edits. Without the EHR's final signed note and edit/version history, CM-08 can only be measured against the transcript, not the clinician's final accepted note, and only via one-off rater exercises rather than continuous monitoring.
  • Wide published omission rates (71–86%). Kernberg 2023 (86%), Arko 2025 (71%) — rates vary with the reference standard used (transcript-based vs. physician-authored-note-based) and with how "clinically relevant element" is operationalized. The element checklist and reference standard must be fixed before a rate is reported or compared across sources.
  • amendment_count is a weak, indirect telemetry proxy. The vendor metrics mapping links an "amended or addendum note count" field to CM-08 as an indirect proxy. It conflates omission-driven re-opens with accuracy corrections (CM-09) and unrelated edits (formatting, dictation fixes, coding changes) — it should not be used as a standalone completeness signal, only as a low-cost screening input pending validation against rater scores.
  • Note Amendment Rate (CM-08/CM-09 boundary). The corpus flags an unresolved "row-13 amendment rate" item — post-signature re-opens that add missing content belong to CM-08; re-opens that correct wrong content belong to CM-09. Clarify with Suki whether their amendment-rate concept distinguishes these, or covers any pre-signature edit.

Algorithm

1 Human Rating / LLM-as-Judge Scoring — PDQI-9/PDSQI-9 Thoroughness Pilot Rapid pilot → scale on agreement

A staged pilot that pulls a sample of session transcript/note pairs (using the source_transcripts[] evidence links as the basis for review), has 2–3 physician raters score the PDQI-9/PDSQI-9 Thoroughness domain, runs an LLM-as-judge prompt on the same rubric over the same pairs, and — if human/LLM agreement is sufficient (r ≥ 0.7) — scales the LLM-as-judge scoring to the full session corpus as an ongoing omission-rate signal. Mirrors the CM-09 Inaccuracy Rate pilot design exactly, with the opposite error type and reference direction.

Units in this Algorithm
Primary
PDQI-9/PDSQI-9 Thoroughness domain score (1–5, higher = better / more complete)
Scored per note by physician raters during the pilot; scored per note by an LLM judge using the identical rubric for both the pilot calibration set and (if agreement is sufficient) the full corpus. Reported as a cohort mean and, separately, as the % of notes scoring below a completeness threshold (i.e., a derived "omission rate").
Secondary
source_transcripts[]-based automated omission-flag rate
Per note, the % of transcript-evidenced clinical elements (history items, medications, findings) that have no corresponding sentence anywhere in the generated note — the reverse direction of CM-09's hallucination flag. Computed for every session, not just the rated sample — serves as a continuous pre-screening signal and as the sampling frame for the next pilot wave.
⚠ This is a screening signal, not a validated completeness score — it tells you where to look, not how complete the note is overall. Do not report it as equivalent to the PDQI-9/PDSQI-9 score until correlation with human ratings is established.
Secondary
Human–LLM agreement (r)
Pearson/Spearman correlation between physician-rater PDQI-9/PDSQI-9 Thoroughness scores and LLM-as-judge scores on the same calibration sample. The gating value for whether automated scoring can be scaled to the full corpus.
⚠ Pipeline gap: until the EHR-side final note and edit history are available (see Missing Feedback Loop above), every score in this algorithm is computed against the transcript, not the clinician's final accepted note — so even a high-agreement, fully-scaled pipeline measures "completeness vs. what was said," not "completeness vs. what the clinician kept."
Omission Rate=COUNT(notes with PDQI-9/PDSQI-9 Thoroughness score below threshold)COUNT(notes rated) × 100
Pilot design (mirrors CM-09 / Afshar 2025b pattern): 1. Sample 50-100 completed session transcript/note pairs via source_transcripts[] 2. 2-3 physician raters score PDQI-9/PDSQI-9 Thoroughness domain (1-5) per note, flagging missing elements 3. LLM-as-judge scores the same pairs using the identical rubric 4. Compute human-LLM agreement r on the calibration sample 5. If r >= 0.7: scale LLM-as-judge scoring to the full session corpus If r < 0.7: refine rubric/prompt and re-pilot before scaling amendment_count is not part of this pilot design; track separately as a low-cost weak-proxy signal only. Reporting cadence: pilot wave (one-time calibration) -> ongoing (if scaled), by cohort / utilization tier
Pseudocode
sample = SELECT 50..100 completed sessions WHERE source_transcripts[] is non-empty for session in sample: pairs[session] = (session.transcript, session.note_content, session.source_transcripts) # Step 1: automated pre-screen (runs on full corpus, not just sample) for session in all_completed_sessions: expected_elements = EXTRACT_ELEMENTS(session.transcript) # meds, history items, findings, etc. flags[session] = [] for element in expected_elements: if NOT ANY(element supported by sentence in session.note_content): flags[session].append("omission") omission_flag_rate[session] = COUNT(flags[session]) / COUNT(expected_elements) # Step 2: human + LLM rating (sample only) for session in sample: human_score[session] = MEAN(rater.score(PDQI9_Thoroughness, pairs[session]) for rater in raters) llm_score[session] = LLM_JUDGE(PDQI9_Thoroughness_rubric, pairs[session]) agreement_r = CORRELATION(human_score, llm_score) # across sample if agreement_r >= 0.7: # scale: apply LLM_JUDGE to all_completed_sessions omission_rate = COUNT(s where llm_score[s] < THRESHOLD) / COUNT(all_completed_sessions) * 100 else: omission_rate = COUNT(s where human_score[s] < THRESHOLD) / COUNT(sample) * 100 # pilot-only estimate dashboard_value = { "omission_rate": omission_rate, "omission_flag_rate": MEAN(omission_flag_rate), "agreement_r": agreement_r }
Expected Trend — Pilot Calibration: Agreement Up, Omission Rate Down

Across successive pilot waves (e.g., as the rubric/prompt is refined and as model versions improve), the expected pattern is rising human–LLM agreement (enabling scale-up) and a declining flagged-omission rate. The agreement line crossing the r = 0.7 threshold is the point at which automated scoring can replace the manual rating sample.

Suki Data — Scoped Role

source_transcripts[] is the key enabling primitive, used in reverse from CM-09: it makes it possible to check whether every transcript-evidenced clinical element has a corresponding note sentence, supporting omission-flag screening at scale without any EHR integration.

Suki also exposes an amendment_count-style telemetry field, but it is a weak, indirect proxy for completeness — it counts note re-opens without distinguishing why the note was re-opened. As with CM-09, Suki has no native survey or human-rating collection mechanism, so PDQI-9/PDSQI-9 Thoroughness ratings must be solicited externally as a pilot. And because of the Missing Feedback Loop, every Suki-native or pilot-based score in this card measures completeness relative to the transcript, not relative to the clinician's final signed note — closing that gap requires either an EHR integration exposing note version history, or a contractual data-sharing provision for note edit logs / final note text.
