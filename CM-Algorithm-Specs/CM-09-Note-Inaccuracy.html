Canonical Measure Algorithm Card

CM-09 — Note Inaccuracy Rate

IQ — Information Quality Pilot / Calibration Design Also known as: Hallucination Rate  ·  Addition Errors  ·  Negation Errors  ·  Freedom from Hallucination (PDQI)

Unit

Unit
% of notes containing ≥1 fabricated or incorrect element
↓ Lower is better

The presence of clinically inaccurate or fabricated content in an AI-generated note — information that was not stated in the encounter, or stated but factually wrong. Distinct from CM-08 (Note Completeness), which measures what was left out. Hallucinations and incorrect facts are less frequent than omissions but more dangerous per event: a note that says nothing about chest pain is an omission; a note that inverts a negation ("denies chest pain" → "reports chest pain") is a patient safety risk.

Gold Standard
PDQI-9 / PDSQI-9 Accuracy domain — 5-point Likert subscale including a falsification/fabrication criterion, scored by physician raters. PDSQI-9 is the AI-note-adapted version; Afshar 2025b validated an LLM-as-judge implementation against physician ratings with agreement sufficient for research-grade use.
Default / Practical
Automated transcript-to-note flagging using Suki's source_transcripts[] evidence-linking primitive — per-sentence hallucination / addition / negation-reversal flags, used as a pre-screening signal and sampling frame for the human/LLM rating pipeline below.
⚠ Ambiguities to Resolve
  • The Missing Feedback Loop. Suki generates a note; the physician reviews, edits, and signs it in the EHR. The physician's edits are the most direct signal of where Suki was wrong — but Suki never sees those edits. Without the EHR's final note text and edit/version history, CM-09 can only be measured against the transcript, not the clinician's final intent, and only via one-off rater exercises rather than continuous monitoring. Verified against Epic's real schema (epic-ehi-kg): HNO_INFO gives note metadata (author, create/last-filed timestamps, signed/unsigned flag) and NOTES_HISTORY_LOG gives an edit-event stream (action type + timestamp) — but no verified Epic table stores full-text version snapshots or a diff of the note against Suki's draft. The gap is real, not just unexplored.
  • Wide published-rate range (3–36%). Baker 2023 (36%), Palm 2025 (31%), Kernberg 2023 (3.2% incorrect facts but 86% omissions) — rates vary enormously by error definition (hallucination vs. incorrect-fact vs. negation-reversal vs. any flagged sentence). The error taxonomy must be fixed before any rate is reported or compared across sources.
  • Reproducibility / cross-replicate consistency. Kernberg 2023 found only 53% of data elements consistent across 3 model runs of the same case — different errors appear on each run, so a single-pass audit may not represent the model's typical behavior. Consider whether a pilot should sample multiple generations per encounter.
  • Note Amendment Rate (CM-08/CM-09 boundary). The corpus flags an unresolved "row-13 amendment rate" item — post-signature re-opens that correct wrong content belong to CM-09; re-opens that add missing content belong to CM-08. Clarify with Suki whether their amendment-rate concept distinguishes these, or covers any pre-signature edit.

Algorithm

1 Human Rating / LLM-as-Judge Scoring — PDQI-9/PDSQI-9 Accuracy Pilot Rapid pilot → scale on agreement

A staged pilot that pulls a sample of session transcript/note pairs (using the source_transcripts[] evidence links as the basis for review), has 2–3 physician raters score the PDQI-9/PDSQI-9 Accuracy domain, runs an LLM-as-judge prompt on the same rubric over the same pairs, and — if human/LLM agreement is sufficient (r ≥ 0.7) — scales the LLM-as-judge scoring to the full session corpus as an ongoing inaccuracy-rate signal.

Units in this Algorithm
Primary
PDQI-9/PDSQI-9 Accuracy domain score (1–5, higher = better / "freedom from hallucination")
Scored per note by physician raters during the pilot; scored per note by an LLM judge using the identical rubric for both the pilot calibration set and (if agreement is sufficient) the full corpus. Reported as a cohort mean and, separately, as the % of notes scoring below an accuracy threshold (i.e., a derived "inaccuracy rate").
Secondary
source_transcripts[]-based automated flag rate
Per note, the % of sentences whose cited transcript evidence does not support the claim (hallucination), has no transcript evidence at all (addition error), or shows inverted polarity vs. the transcript (negation error). Computed for every session, not just the rated sample — serves as a continuous pre-screening signal and as the sampling frame for the next pilot wave.
⚠ This is a screening signal, not a validated accuracy score — it tells you where to look, not how accurate the note is overall. Do not report it as equivalent to the PDQI-9/PDSQI-9 score until correlation with human ratings is established.
Secondary
Human–LLM agreement (r)
Pearson/Spearman correlation between physician-rater PDQI-9/PDSQI-9 Accuracy scores and LLM-as-judge scores on the same calibration sample. The gating value for whether automated scoring can be scaled to the full corpus.
⚠ Pipeline gap: until the EHR-side final note and edit history are available (see Missing Feedback Loop above), every score in this algorithm is computed against the transcript, not the clinician's final accepted note — so even a high-agreement, fully-scaled pipeline measures "accuracy vs. what was said," not "accuracy vs. what the clinician kept."
Inaccuracy Rate=COUNT(notes with PDQI-9/PDSQI-9 Accuracy score below threshold)COUNT(notes rated) × 100
Pilot design (Afshar 2025b pattern): 1. Sample 50-100 completed session transcript/note pairs via source_transcripts[] 2. 2-3 physician raters score PDQI-9/PDSQI-9 Accuracy domain (1-5) per note, flagging sentences 3. LLM-as-judge scores the same pairs using the identical rubric 4. Compute human-LLM agreement r on the calibration sample 5. If r >= 0.7: scale LLM-as-judge scoring to the full session corpus If r < 0.7: refine rubric/prompt and re-pilot before scaling Reporting cadence: pilot wave (one-time calibration) -> ongoing (if scaled), by cohort / utilization tier
Pseudocode
sample = SELECT 50..100 completed sessions WHERE source_transcripts[] is non-empty for session in sample: pairs[session] = (session.transcript, session.note_content, session.source_transcripts) # Step 1: automated pre-screen (runs on full corpus, not just sample) for session in all_completed_sessions: flags[session] = [] for sentence in session.note_content: evidence = session.source_transcripts[sentence] if evidence is empty: flags[session].append("addition_error") elif NOT SUPPORTS(evidence, sentence): flags[session].append("hallucination") elif POLARITY(evidence) != POLARITY(sentence): flags[session].append("negation_error") flag_rate[session] = COUNT(flags[session]) / COUNT(sentences in session.note_content) # Step 2: human + LLM rating (sample only) for session in sample: human_score[session] = MEAN(rater.score(PDQI9_Accuracy, pairs[session]) for rater in raters) llm_score[session] = LLM_JUDGE(PDQI9_Accuracy_rubric, pairs[session]) agreement_r = CORRELATION(human_score, llm_score) # across sample if agreement_r >= 0.7: # scale: apply LLM_JUDGE to all_completed_sessions inaccuracy_rate = COUNT(s where llm_score[s] < THRESHOLD) / COUNT(all_completed_sessions) * 100 else: inaccuracy_rate = COUNT(s where human_score[s] < THRESHOLD) / COUNT(sample) * 100 # pilot-only estimate dashboard_value = { "inaccuracy_rate": inaccuracy_rate, "flag_rate": MEAN(flag_rate), "agreement_r": agreement_r }
Expected Trend — Pilot Calibration: Agreement Up, Inaccuracy Rate Down

Across successive pilot waves (e.g., as the rubric/prompt is refined and as model versions improve), the expected pattern is rising human–LLM agreement (enabling scale-up) and a declining flagged-inaccuracy rate. The agreement line crossing the r = 0.7 threshold is the point at which automated scoring can replace the manual rating sample.

Suki Data — Scoped Role

source_transcripts[] is the key enabling primitive: it makes transcript-to-note auditing tractable at scale, supporting hallucination-rate, addition-error, negation-error, and ICD-10-fidelity flagging today, without any EHR integration.

However, Suki has no native survey or human-rating collection mechanism — PDQI-9/PDSQI-9 ratings must be solicited externally as a pilot (physician raters plus LLM-as-judge), following the Afshar 2025b calibration pattern. And because of the Missing Feedback Loop, every Suki-native or pilot-based score in this card measures accuracy relative to the transcript, not relative to the clinician's final signed note — closing that gap requires either an EHR integration exposing note version history, or a contractual data-sharing provision for note edit logs / final note text.

⚠ Verified against Epic's real EHI schema (not the vendor-metrics-catalog guesses this card previously relied on): HNO_INFO and NOTES_HISTORY_LOG exist and give note metadata and edit-event timestamps, but no verified Epic table in this schema stores full-text note version snapshots or a Suki-draft-vs-final diff — closing the Missing Feedback Loop for CM-09 would require a table type not found here, not just access to one that already exists.
