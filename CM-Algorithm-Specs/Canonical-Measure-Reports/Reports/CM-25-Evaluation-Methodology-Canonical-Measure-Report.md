# CM-25 Evaluation Methodology Quality
## Canonical Measure Report — Internal Draft

**Measures covered:** CM-25 Evaluation Methodology Quality (meta-measure; applies to every other canonical measure's source literature, not to Suki directly)
**Status:** Internal draft for review and editing before sharing externally — **includes an open team decision on whether this measure should remain in the canonical set at all**

---

## What This Measure Captures

**CM-25 Evaluation Methodology Quality** is a meta-measure: the rigor and validity of a *source paper's* study design and measurement approach — inter-rater reliability, sample representativeness, benchmark dataset availability, and methodological adequacy. It is not a clinical outcome, and it is not a property of Suki's product. It assesses whether the *other* measures reported in a given study are trustworthy.

This report opens with the flag that appears at the top of the source corpus file, because it should not be buried:

> **Team action required:** This is not a system quality measure and does not belong in the D&M framework as an AI-derived category. Methodology quality assessment should be conducted by the human research team, not generated by AI. The categorization and content in the corpus represent AI-derived observations only — the team should own all final judgments about study quality. Consider removing this as a canonical measure and integrating methodology notes directly into each paper's record instead.

This report documents the mechanics as they currently exist in the review (ICC, evidence-design tiering), so that if the team decides to retain CM-25, the algorithm card and this report are ready — but it does not advocate for retention.

**Why this matters for Suki's value story:** it doesn't, directly — and that is the point. CM-25 exists to help the review team weigh *other* measures' evidence correctly (e.g., knowing that Afshar 2025b is a stepped-wedge RCT while most QI-study papers in the corpus are pre-post with no control group changes how much weight their respective effect sizes should carry in synthesis). It should never appear in a customer-facing or Suki-product-facing context.

---

## Where ICC and Evidence-Tiering Are Already Used in the Review

Even though CM-25 as a standalone canonical measure is a removal candidate, the two mechanics it documents — inter-rater reliability and evidence-design tiering — are not new inventions; they are already load-bearing elsewhere in this review's own methodology:

- **CM-09 (Note Inaccuracy Rate)** uses a human-LLM agreement threshold (r ≥ 0.7) as the gate for whether automated PDQI-9/PDSQI-9 scoring can be scaled from a pilot sample to the full session corpus — structurally the same inter-rater-reliability logic CM-25 documents.
- **The evidence-design tier hierarchy** (RCT > propensity-matched observational > pre-post QI, no control) is already used informally throughout the corpus's synthesis language — e.g., "Afshar 2025b (RCT, stepped-wedge, 24 weeks) > Pearlman 2025 (propensity-matched observational) > most QI studies (pre-post, no controls)" appears verbatim in CM-25's own source file as the working hierarchy the team already applies.

This is the strongest argument *for* keeping some version of this content: the mechanics are genuinely useful and already in active use. The open question is whether they need to be a numbered canonical measure sitting alongside CM-01 through CM-24, or whether they belong instead as a standing methodology appendix / per-paper metadata field in the review database — which is exactly the alternative the corpus's own flag proposes.

## The Removal Question

This is the central structural issue for CM-25, and unlike every other report in this set, the resolution is not a data or integration gap — it is a **taxonomy decision** the team needs to make explicitly.

```
Canonical Measures (CM-01 ... CM-24)          CM-25
────────────────────────────────────          ─────────────────────────
Score a Suki-observable outcome        vs.     Scores whether a SOURCE PAPER's
(documentation time, note accuracy,            OWN measurement of one of those
burnout, adoption, etc.)                       outcomes can be trusted

           │                                              │
           └──────────────► used to weight ◄──────────────┘
                          how much confidence to place
                          in that paper's reported numbers
```

**What is achievable today:** the mechanics work and are already informally in use elsewhere in the review (see above). If the team wants a standing per-paper rigor score, the ICC formula and tier rubric documented on the CM-25 algorithm card are ready to use as-is.

**What is missing:** a decision. Three options, not mutually exclusive:

1. **Retain CM-25 as-is** — keep it as a numbered canonical measure, understood internally as a review-methodology tool, never surfaced externally.
2. **Fold it into per-paper metadata** — per the corpus's own flag, remove the standalone canonical-measure framing and attach an ICC value + evidence tier directly to each paper's record in the review database.
3. **Split the difference** — keep the mechanics documented (this report + the algorithm card) as reference material for the review team, but formally drop the "CM-25" numbering so it doesn't imply parity with the 24 Suki-outcome measures when the canonical set is presented externally.

This report does not recommend one of the three — that judgment belongs to the human research team, consistent with the corpus's own flag that AI-derived categorization should not make this call.

## Open Questions for the Review Team

These replace the "Open Questions for Suki" section for this measure only:

1. Should CM-25 remain a numbered canonical measure, or be retired in favor of per-paper ICC/tier metadata fields, per the corpus's own removal flag?
2. If retained, who owns the evidence-tier rubric going forward, and how are borderline design classifications (e.g., partially-matched observational studies) adjudicated?
3. Should the ICC and evidence-tier components ever be combined into a single composite score, or is the two-component "profile" (as documented on the algorithm card) the permanent reporting convention?
4. Does the team want a standing policy that CM-25 (in any form) never appears in Suki-facing or customer-facing materials, given that it evaluates the literature, not Suki?
