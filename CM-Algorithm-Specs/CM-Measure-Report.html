Canonical Measure Data Requirements

Prepared by: Regenstrief Suki Research Team Date: May 2026 For: Suki Data & Analytics Team (Amita, Sudha) Status: For review and feedback

Purpose. This document identifies the data inputs required to compute each priority canonical measure for Suki's ambient AI platform. For each measure, it specifies what must come from the EHR partner and what Suki already provides. It is intended to inform Suki's data pipeline and admin console development.

Scope. Measures are organized into Financial and Operational categories. Each row lists the raw inputs needed — not a complete algorithm. The implied comparison for all measures is pre-Suki vs. post-Suki, per provider, using each provider's adoption date (first completed session) as the pre/post boundary.

ℹ

Universal Suki input for all measures: Provider-level usage logs linking each provider ID to their Suki adoption date and session activity. For most measures, this is Suki's primary contribution — a flag identifying which providers are Suki users and when adoption occurred.

The exception is the ICD-10 Suggestion Match Rate (CM-21b), which additionally requires Suki-generated diagnosis codes from the structured-data API endpoint.

Deferred

Measures Not in Current Scope

HCC Capture Rate — HCC capture (risk-adjustment diagnosis completeness) requires applying the CMS HCC v28 crosswalk to final billed ICD-10 codes. This step is not in Suki's current EHR data pull. ma_patient_count (Medicare Advantage patient count) is available from Epic and Athena as relevant population context, but HCC capture computation itself is deferred pending pipeline readiness. Estimated impact from published literature: +$9,685/provider/year (Boyter/KLAS 2025).
Note Quality (CM-09, CM-10, CM-11) — Note accuracy, overall quality (PDQI), and verbosity measures are deferred. Suki's note quality processes are currently in flux; these measures will be re-evaluated once internal processes stabilize.
